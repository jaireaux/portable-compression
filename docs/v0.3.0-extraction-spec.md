# Portable Compression v0.3.0 extraction specification

Status: release acceptance complete.

## Scope

Portable Compression extracts ZIP and TAR.GZ archives through the same self-contained JavaScript helper used for deterministic creation. Runtime execution uses no OS archive utility, MCP server, network service, Python module, or externally installed compression package.

## One-invocation attempts

An extraction attempt consists of exactly one helper command. The helper reads and validates the archive, validates the destination, detects collisions, stages files, publishes them, verifies final bytes, and reports JSON. There are no separate preflight, listing, checksum, directory-creation, or postflight commands.

No-collision extraction completes in one attempt without a plugin-level prompt. When collisions exist and the user did not choose a policy in advance, the first attempt writes nothing and returns `decision_required` with the exact user-facing question in `prompt`. In the same response that reports the collisions and complete helper JSON, ChatGPT must repeat that returned prompt verbatim as its final line and then wait. The expected value is **Collision found: (o)verwrite, (k)eep both, or (c)ancel?** JSON alone is not a complete response to `decision_required`. After the user explicitly chooses a policy, ChatGPT makes one new self-contained attempt with that policy. It must not infer or reuse a choice from an earlier collision. This two-attempt collision flow avoids depending on interactive stdin, which is not reliable across ChatGPT Work and Codex hosts.

## Collision policies

- `overwrite`: replace colliding regular files. Never follow or replace through a symbolic link.
- `keep-both`: preserve existing files and assign the smallest available deterministic numbered name, beginning with `name (2).ext`.
- `cancel`: write nothing and report cancellation.

A file/directory type conflict is an error rather than an overwrite choice. The helper does not infer a collision policy.

## Safety

Before writing, reject encrypted or unsupported ZIP entries; TAR types other than regular files and directories; ZIP or TAR symlinks, hard links, and special files; duplicate normalized member paths; absolute paths; Windows drive paths; backslashes; NULs; empty, dot, or parent components; excessive path length or depth; excessive entry count; and excessive archive or expanded size.

Resolve every output beneath the selected extraction directory. Reject an existing extraction directory, ancestor, or target that is a symbolic link where applicable. Decode and validate all members before staging. Stage files in a private sibling directory, verify staged bytes, publish without following links, verify final bytes, and clean up staging after success or failure. As with archive creation, safety assumes the user-controlled destination hierarchy is not concurrently replaced by another process.

## JSON results

Successful extraction returns `ok`, `operation`, `format`, `input`, `output_directory`, `archive_bytes`, `extracted_bytes`, `file_count`, `collision_policy`, `renamed_count`, and archive `sha256`.

A collision requiring input returns `ok: false`, `status: "decision_required"`, `operation`, `format`, `output_directory`, `collision_count`, a bounded `collisions` list with `collisions_truncated`, `choices`, and `prompt`.

Cancellation returns `ok: false`, `status: "cancelled"`, the operation and format, output directory, and collision count. Other failures return `ok: false` and an error message on stderr with a nonzero exit status.

## ChatGPT Work acceptance evidence — 2026-09-08

The local v0.3.0 development plugin was exercised in ChatGPT Work with the two established XML fixtures. ZIP and TAR.GZ each completed a no-collision extraction through exactly one helper invocation and reported 2 files and 1,799 extracted bytes. ZIP reported its established 1,061-byte archive and SHA-256 `3b2f50b7e97d7031b6cc51c0a485b9c8ed41e5e0792f81f006e25158fae76aa8`; TAR.GZ reported its established 536-byte archive and SHA-256 `1cd5a09012d349fa6e3817f017e66db81dc3b37917eb97280dbb4f02447f8998`.

For both formats, a repeat into the same destination reported two collisions before writing. User-selected cancel wrote nothing, keep-both succeeded with `renamed_count: 2`, and overwrite succeeded with `renamed_count: 0`. One TAR.GZ attempt initially reused the preceding keep-both choice from conversational context; an explicit instruction not to reuse or infer a prior policy restored the required decision-first flow, after which overwrite succeeded.

A deliberately unsafe TAR.GZ containing `../portable-compression-v030-escape-test.txt` was rejected with exit status 1 and `{"ok":false,"error":"Unsafe archive path: ../portable-compression-v030-escape-test.txt"}`. Validation rejected the member before staging or publication. Johnny reported zero approval prompts across the complete Work extraction sequence. This is acceptance evidence for those sessions, not a guarantee about host-managed approvals in every environment.

## Linux acceptance evidence — 2026-09-08

The uncommitted v0.3.0 candidate was transferred to an isolated directory on Langston North Media and tested on Ubuntu 24.04.4 LTS x86-64 with Node.js 22.23.2; the installed Codex CLI reported 0.153.4. The complete JavaScript test suite, plugin validator, and skill validator passed on Linux.

Direct helper acceptance used the established 1,061-byte ZIP and 536-byte TAR.GZ fixtures. Both no-collision extractions returned 2 files, 1,799 extracted bytes, `collision_policy: "none"`, and the established format-specific SHA-256 values. Both formats then returned `decision_required` with the same two colliding XML paths. Cancel, keep-both, and overwrite all produced the required results; keep-both reported `renamed_count: 2`, while overwrite reported `renamed_count: 0`.

The traversal fixture was rejected with the same unsafe-path error as Work. A separate acceptance assertion confirmed that neither the requested extraction directory nor the escaped target was created. These direct SSH/helper tests validate Linux runtime behavior independently of the installed-plugin acceptance below.

The candidate was then installed from an isolated local marketplace and exercised through Codex CLI 0.153.4 in Termius with normal approval handling. The first ZIP attempt exposed an ambiguous instruction for resolving the helper relative to `SKILL.md`: Codex resolved from the parent `skills` directory and the single invocation failed with `MODULE_NOT_FOUND`, without extracting anything. The instruction now explicitly names the directory containing the exact `SKILL.md` file (`skills/compress-files`), and a regression assertion protects that wording.

After reinstalling the corrected candidate, a recorded Codex CLI run covered eleven helper invocations: clean, decision-required, cancel, keep-both, and overwrite for both ZIP and TAR.GZ, plus unsafe-path rejection. Fresh extractions returned the established metadata: 2 files and 1,799 extracted bytes; ZIP 1,061 bytes with SHA-256 `3b2f50b7e97d7031b6cc51c0a485b9c8ed41e5e0792f81f006e25158fae76aa8`; TAR.GZ 536 bytes with SHA-256 `1cd5a09012d349fa6e3817f017e66db81dc3b37917eb97280dbb4f02447f8998`. Both formats reported the two expected XML collisions before writing. Cancel returned `status: "cancelled"`; keep-both returned `renamed_count: 2`; overwrite returned `renamed_count: 0`. The unsafe TAR.GZ was rejected before publication. No preflight, separate listing, checksum, directory-creation, or postflight command was used. The raw recording is retained locally as `outputs/v030-linux-extraction-transcript-2.txt` and is evidence, not a release payload.

The recorded run also exposed a presentation defect: after both `decision_required` results, Codex reported the complete JSON but did not display the user-facing collision question. The helper behaved correctly and wrote no files. The helper now includes the exact question in a machine-readable `prompt` field; the skill requires Codex to repeat that returned value verbatim as its final line and wait. Regression assertions protect both the JSON field and the conversational contract.

After both development installations were cache-busted and refreshed, a fresh LNM Codex CLI interaction returned the new `prompt`, displayed **Collision found: (o)verwrite, (k)eep both, or (c)ancel?**, waited for an explicit answer, and applied `k` as keep-both in one new helper invocation. The result reported 2 files, 1,799 extracted bytes, `collision_policy: "keep-both"`, `renamed_count: 2`, and the established ZIP SHA-256.

A fresh Mac ChatGPT Work interaction then completed the same ZIP extraction with the established metadata. Its repeat extraction returned and displayed the exact collision prompt, waited for the user's `o`, and completed one overwrite invocation with `collision_policy: "overwrite"` and `renamed_count: 0`. One earlier fresh Mac attempt was blocked before helper execution with `zsh:1: operation not permitted: node` and produced no JSON or files; a subsequent attempt succeeded without a plugin change. That event is treated as a transient host-runtime denial and not as a failed helper result. Together, the Mac and LNM retests close the collision-presentation acceptance gap.

LNM originally prevented Codex's bubblewrap sandbox from creating user namespaces because Ubuntu's AppArmor restriction for unprivileged user namespaces was enabled. A narrowly scoped `codex-userns` AppArmor profile now grants `userns` to the resolved Codex 0.153.4 executable, and `codex sandbox true` succeeds. This fixes sandbox startup; it does not suppress normal Codex approvals. The executable path is version-specific and must be updated when Codex is upgraded. In the recorded cold start, Codex requested approval once to read the installed skill and once to execute the helper; subsequent attempts requested helper-execution approval. These are host-managed permission boundaries, not extra plugin-operation commands. The directory had already been trusted, so no directory-trust prompt was counted.
